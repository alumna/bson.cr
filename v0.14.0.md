## Text to add to CHANGELOG.md

```markdown
## 0.14.0 - 2026-08-18

### Added
* **regex:** Added `BSON::Regex` with `pattern` and `options` as text. Decode does not compile PCRE. Use `#to_regex` / `#to_regex?` when you need a Crystal `Regex`.
* **datetime:** Added `BSON::DateTime` (`int64` milliseconds). Values outside Crystal `Time` (for example Y10K) are kept. Use `#to_time` / `#to_time?`.
* **error:** Added `BSON::Error` for bad BSON bytes and bad Extended JSON.
* **core:** Added `BSON.parse` / `parse?`, `from_json?`, `from_io?`, and `BSON.build`.
* **core:** `BSON::Builder` is public so Cryomongo can write a document in one pass.
* **decimal128:** Added optional `require "bson/optional/big_decimal"` for `BigDecimal` convert.
* **object_id:** After `fork` on Unix, process-unique bytes and the counter are rebuilt.

### Changed
* Decode of BSON datetime now returns `BSON::DateTime` instead of `Time`.
* Decode of BSON regex now returns `BSON::Regex` instead of Crystal `Regex`.
* The default Decimal128 path no longer does `require "big"`.
* Missing keys raise `KeyError`.

### Performance (Cryomongo)
* `BSON.build` and public `Builder` avoid repeated `[]=` rebuilds when you write a command or a reply.
* Nested documents stay views of the parent buffer (`BSON.view`). No extra copy per subdocument.
* Regex decode no longer compiles PCRE. Queries that only store or send the pattern stay cheap.
* DateTime is two words (`Int64`). No `Time` allocation on decode.
* `parse?` / `from_json?` let the driver reject a bad message without a full exception path when you only need nil.
* ObjectId stays 12 inline bytes. Generation uses `Atomic`, not a mutex.

### Fixed
* Y10K and other out-of-range datetimes no longer fail decode.
* Unusual or invalid regex patterns can round-trip.
* LibGMP is not linked unless you require the BigDecimal helper.
```

## Pull request title

`Complete BSON types for Cryomongo: DateTime, Regex, parse?, and one-pass Builder`

## Pull request body

```markdown
This release finishes the BSON shard for the Cryomongo update.

### Types
- `BSON::DateTime` stores the full `int64` millisecond range. Y10K works. Convert with `#to_time` / `#to_time?`.
- `BSON::Regex` stores pattern and options as text. Decode does not compile PCRE. Convert with `#to_regex` / `#to_regex?`.
- `BSON::Serializable`, `Hash`, `Array`, and `NamedTuple` still accept `Time` and Crystal `Regex` fields.

### Cryomongo API
- `BSON.build { |b| ... }` and public `BSON::Builder` write a document in one pass.
- `BSON.parse` / `parse?`, `from_json?`, `from_io?` for driver I/O.
- `BSON::Error` for bad bytes and bad ExtJSON. Missing keys raise `KeyError`.

### Other
- `require "bson/optional/big_decimal"` is the only LibGMP path.
- ObjectId process-unique bytes reset after `fork` on Unix.
- Official corpus now includes Y10K. Full suite: 1051 examples.

Contract changes Cryomongo must apply:
- `bson[key]` for a datetime is `BSON::DateTime`, not `Time`.
- `bson[key]` for a regex is `BSON::Regex`, not `Regex`.
- Prefer `BSON.build` over many `[]=` calls.
```

## GitHub Releases page

**Title:** `v0.14.0 — DateTime, Regex, and Cryomongo builder API`

**Body:**

```markdown
Pure Crystal BSON for MongoDB 8.0. This tag is meant for the Cryomongo driver update.

### Use in Cryomongo
- Build commands with `BSON.build` or `BSON::Builder` (one buffer, not one rebuild per field).
- Dates are `BSON::DateTime`. Call `#to_time` at the model edge.
- Regex values are `BSON::Regex`. Compile only with `#to_regex` when you match text.
- Use `parse?` / `from_json?` when a bad message should be `nil`.
- Nested documents are views. Keep the parent document alive.

### Also in this release
- Full datetime range, including Y10K.
- No PCRE compile on regex decode.
- No LibGMP unless you `require "bson/optional/big_decimal"`.
- ObjectId unique bytes after `fork` on Unix.

1051 spec examples pass, including the official MongoDB BSON corpus.
```
